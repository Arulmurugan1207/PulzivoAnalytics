What this test measures

The browser calls Google's PageSpeed Insights v5 API (runPagespeed). Google loads the page in a lab and returns Lighthouse data. The performance score is that lab visit, from 0 to 100. 90 and above is good. 50 to 89 needs work. Below 50 is poor.

LCP is Largest Contentful Paint. CLS is Cumulative Layout Shift. Both numbers on the cards are from the lab visit. Good, needs work, and poor use Google's published cutoffs: LCP good at 2.5 seconds or faster, CLS good at 0.1 or less.

INP, Interaction to Next Paint, is a field metric. When Chrome has enough real visits, Google includes that INP and this page shows it, labelled as field data for the URL or for the whole site. When that data is missing, Lighthouse does not invent an INP. The card shows Total Blocking Time instead, and the label says it is a lab proxy. TBT is not INP. Its own cutoff is 200 ms for good and 600 ms for the start of poor.

How to read the result

  • Green is good, amber is needs work, red is poor. Grey means the test did not report that number.
  • The top three opportunities are the Lighthouse suggestions with the largest estimated time savings, written in plain language. The estimate is for this lab run only.
  • A lab score moves around. Run it twice before you treat a small change as real. It still will not match every visitor's phone or network.
  • localhost and private network addresses are rejected here, because Google's servers cannot open them.
  • If Google's shared quota is used up, the page says so. Try again later. No account is required. A PageSpeed API key in the site config, not stored in git, makes repeated checks more reliable.
